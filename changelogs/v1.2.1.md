## :bug: Critical Crash Fixes

- **`outfit_lock` Upvalue Crash** — `outfit_lock` was referenced inside `tick()` every frame but never declared. Defined as a proper global table `{ enabled, components, props }`. The script no longer crashes on load.
- **`teleport_to_player` / `smart_kick` / `network_timeout` / `send_friendly_sms` Upvalue Crash** — These functions referenced `p` and `p_name` as free variables captured from a dynamic submenu loop, causing a nil crash whenever any player-targeting option was clicked. All functions now explicitly accept `(p, p_name)` as parameters and the GUI callbacks pass them via closures.
- **`save_config()` Stack Overflow** — A duplicate local `save_config()` function was declared that called itself recursively, causing an immediate stack overflow. The duplicate has been removed; the global `save_config()` at the top of the file is now the only definition.
- **Orphaned Global-Scope Code** — `outfit_lock.enabled = false` / `.components` / `.props` assignments existed after the closing `end)` of `gui.register_menu`, executing as top-level code outside any function. Removed — `outfit_lock` is correctly initialized in the global declaration block.

## :shield: Fixed — Protection System (Block Script Events + Block Sync Nodes)

**Block Script Events**
- Implements `event.add_script_event_blocker(hash)` / `event.remove_script_event_blocker(hash)` per the Ethereal API spec (previously used an invalid callback-based approach)
- Registers and unregisters dynamically from `tick()` based on toggle state using an idempotent guard flag
- Blocks 8 known malicious TSE hashes: Send to Hospital, Force Wanted Level, Bounty Set, CEO Kick, MC Kick, Report Player Spam, Force Bail, Spectate Exploit
- When enabled, logs all incoming TSEs to the Ethereal log (hash + sender + arg count) for identifying new attack vectors

**Block Sync Nodes**
- Implements `node.create_hook(node_id, callback, per_player, force_in_scope)` per the Ethereal `node` API
- Hooks 4 critical network sync data nodes: `CPlayerGameStateDataNode`, `CPlayerAppearanceDataNode`, `CPedHealthDataNode`, `CVehicleProximityMigrationDataNode`
- Callback drops inbound syncs from non-local players when toggle is active; returns `false` (pass-through) when disabled
- Hooks registered once on first enable; callback gate handles subsequent on/off toggling without re-registration

## :screwdriver: Native API Corrections

| Incorrect Call | Corrected To | Reason |
|---|---|---|
| `WEAPON.GET_CURRENT_PED_WEAPON_HASH(ped)` | `WEAPON.GET_SELECTED_PED_WEAPON(ped)` | Former native does not exist in GTA5 |
| `FIRE.ADD_EXPLOSION(..., 0.0)` (8 args) | `FIRE.ADD_EXPLOSION(..., 0.0, false)` (9 args) | Current GTA build requires `noDamage` as 9th param |
| `WATER.GET_WATER_HEIGHT_NO_WAVES(x,y,z, 0.0)` | `WATER.GET_WATER_HEIGHT_NO_WAVES(x, y, z)` | 4th param is an output pointer; passing `0.0` was corrupting the call |
| `event.add_script_event_blocker(function(...) end)` | `event.add_script_event_blocker(hash: int)` | API takes a single integer hash, not a callback |
| `load_config` inner `if val ~= nil` misaligned outside type-check block | Correctly nested inside `if type(ref) == "table"` | Values were being written to non-table state entries, causing runtime errors |

## :shield: Hotfix — Godmode & Invisibility Upgraded to Network-Synced

**Previously:** Both features were local-only, using `ENTITY.SET_ENTITY_INVINCIBLE` and `ENTITY.SET_ENTITY_VISIBLE`. Other players could still kill you and see you normally.

**Now:** Both use a multi-layer network approach:

**Godmode (3 layers)**
- **Layer 1:** `PLAYER.SET_PLAYER_INVINCIBLE(pid, true)` — Player-level invincibility flag, synced to all other clients. Other players' games recognize you as invincible.
- **Layer 2:** `ENTITY.SET_ENTITY_PROOFS(ped, true×8)` — Full bullet/fire/explosion/melee/steam/drown/water proof applied every frame.
- **Layer 3:** Health + armor refill every frame as a hard safety net against anything that bypasses flags.
- Clears proofs cleanly when disabled (respects `Explosion Immunity` toggle if active).

**Invisibility (3 layers)**
- **Layer 1:** `NETWORK.NETWORK_CONCEAL_PLAYER(pid, true, true)` — Removes the player from all other clients' render lists and radar.
- **Layer 2:** `ENTITY.SET_ENTITY_ALPHA(ped, 0)` — Zeroes local entity alpha.
- **Layer 3:** `ENTITY.SET_ENTITY_VISIBLE(ped, false)` — Hides ped from local render pipeline.
- All three layers cleanly restored (`RESET_ENTITY_ALPHA`, `SET_ENTITY_VISIBLE(true)`, `NETWORK_CONCEAL_PLAYER(false)`) when toggled off.

> :warning: **Note:** `NETWORK_CONCEAL_PLAYER` is an official Rockstar-used native (hash `0xBBDF066252829606`), originally for scripted game modes. Effectiveness may vary depending on session host script authority and Ethereal's network hook scope. Short note, YOU MUST BE HOST/SH TO TRULY HIDE OR CUSTOM SCRIPTS CAN REVEAL YOU!!
